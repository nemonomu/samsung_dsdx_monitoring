# 매뉴얼 캡처 선택과 저장

- 모든 국가·쇼핑몰에서 같은 선택 규칙을 사용한다.
- 대표 캡처는 쇼핑몰, 공통/제품군 범위, 컬럼별로 독립적으로 저장한다.
  `photos[].primaryFor`의 `범위:컬럼` 키에서 가장 높은 정수 우선순위가 대표다.
- 기존 자료에 대표 설정이 없으면 사용자 편집 캡처를 먼저 고른다.
  `user_photo_<생성시각>`은 생성시각 내림차순, 그 외에는 캡처 날짜를 사용한다.
  변경하지 않은 최초 자료는 기존 개요/상세 우선순위를 유지한다.
  이전 자료에는 편집 시각이 없으므로 생성·캡처 날짜가 실제 최종 수정 순서를 보장하지는 않는다.
- 기존 기본값은 로드할 때 추론하고 이후 저장 시 함께 보관한다. 기존 캡처를 삭제하거나
  운영 DB를 일괄 덮어쓰는 마이그레이션은 필요하지 않다.
- `현재 이미지 교체`는 같은 캡처를 갱신한다. `별도 캡처 추가`는 기존 캡처를 유지한다.
  적용한 캡처는 현재 컬럼의 대표로 설정하며 다른 컬럼의 대표 설정은 유지한다.
- 이미지의 `적용 후 저장`, `이 캡처를 대표로 설정`은 기존 버전 충돌 검사를 거쳐
  매뉴얼 변경 사항을 서버에 저장한다. 실패하면 변경 내용을 유지하며 저장 버튼으로 재시도한다.
- 이전 이미지와 대표 설정은 기존 매뉴얼 버전 이력에 남는다.
- 상단 안내와 방문 방법은 같은 `routeNotes.main` / `routeNotes.bsr`를 읽으며 줄바꿈을 보존한다.

검증: `node --test tests/test_dx_manual_photos.js tests/test_dx_manual_groups.js`,
`python -B tests/test_dx_manual.py`, `python -B tests/test_dx_manual_photos_browser.py`,
`python -B tests/test_dx_manual_delete_browser.py`.
