# Layer1 수집데이터 통계

## 화면 확인

- Layer1 사이드바 **수집데이터 통계**: `/dx/layer1/collection-statistics/`
- 국가, 제품군, 업체, 최근 5/7/14/49일과 기준일을 선택한다.
- **정상 중앙값 (기준: 28일)** 열은 정상 여부와 관계없이 기준일의 검수 대상 데이터일에 적용되는 MAIN·BSR 기준값을 표시한다. 기존 검수 오프셋에 따라 SEA·SEDA는 D-1, 나머지 국가는 당일을 적용하며 각 행에 적용 데이터일을 표시한다. 예: 10/20 조회 시 SEA는 10/19 기준값을 표시한다. 대상 데이터일을 제외한 이전 28일의 비교 가능한 최소 5일 이력을 사용하며, 화면 조회 기간을 바꿔도 같은 날짜의 기준값은 바뀌지 않는다.
- BSR 100개 규칙은 **고정 기준**으로 표시한다. 이력이 부족하거나 검수 대상 데이터일의 집계가 없으면 임의의 다른 날짜 값으로 대신하지 않고 사유를 표시한다. 여러 수집 시간대의 기준값은 합산하지 않고 시간대별로 구분한다.
- 일별 MAIN·BSR·총수량은 조회 기준일까지 원래 데이터일로 표시한다. 수집 중·조회 실패·미집계 상태도 구분한다. API의 `baseline_dates`는 중앙값 조회에만 사용하며 원본 수집 날짜·시간대 변환·일별 건수·이상 판정은 변경하지 않는다.
- 총 건수는 각 국가 Layer1 표의 총 건수와 동일하다. MAIN+BSR의 합산 값이 아니다. SEM과 TSE의 MAIN 기준 업체 등 기존 화면 기준을 유지한다.

기존 Layer1 대시보드 및 SEA Retail 페이지에서는 주간 통계를 불러오지 않는다. 저장된 과거 중앙값과 업체별 BSR 규칙을 받아 현재 MAIN·BSR 건수로 업체 행, 제품군, 국가 상태를 판정한다. 총 건수는 참고용으로 표시한다.

| 상황 | Layer1 표시 |
| --- | --- |
| MAIN: 이전 28 데이터일 중 비교 가능한 최소 5일의 MAIN 중앙값보다 15% 미만 감소 | MAIN 경고 없음 |
| MAIN: 같은 기준보다 15% 이상 30% 미만 감소 | 파란 **확인 필요** |
| MAIN: 같은 기준보다 30% 이상 감소 | 빨간 **이상** |
| MAIN: 같은 기준보다 30% 이상 증가 | 파란 **확인 필요** |
| 총수량 | 참고용 표시, 별도 판정 없음 |
| 대상 BSR: 같은 기간의 유효한 최소 5일 중앙값보다 15% 이상 20% 미만 감소 | 파란 **확인 필요** |
| 대상 BSR: 같은 기준보다 20% 이상 감소 | 빨간 **이상** |
| 대상 BSR: 감소율 15% 미만 또는 증가 | BSR 경고 없음, 100개 미만도 허용 |
| 완료된 MAIN 0건 / 전체 미수집 / 원본 조회 오류 | 이상 / 미수집 / 오류 유지 |
| 이력 부족 / 비교 API 장애 / 사용할 수 없는 통계 | 검증 대기, 정상으로 처리하지 않음 |
| 재수집·삭제로 배치나 건수가 변경됨 | 같은 대상일의 과거 중앙값에 현재 건수를 넣어 즉시 재판정 |
| 수집 시간 미완료 | 수집 중 (TSE는 기존 수신 즉시 판정 정책 유지) |

대상 BSR은 SEA Lowes REF·LDY, SEA Amazon TV, SIEL Amazon TV·REF·LDY, SEG Amazon TV·REF이다. SEM HomeDepot·Coppel의 BSR은 기존 중앙값 대비 30% 이상 감소 기준을 유지하고, 그 외 리테일러의 BSR은 기존 100개 고정 기준을 유지한다. 신규 대상은 최초 5일 관찰 후 비교한다.

MAIN과 BSR을 각각 비교한다. 이상과 확인 필요가 함께 있으면 이상을 우선한다. 둘 다 판정 가능하고 경고가 없어야 정상이다. 기존 국가별 총 건수 최소값이나 평균 대비 절대 건수 차이 판정은 최종 상태에 사용하지 않는다. MAIN 0건, 전체 미수집 및 조회 오류는 계속 표시한다. 이력이 부족하면 통계 상세에 비교 이력 부족을 표시한다. BSR 경고일은 기준 이력에서 제외하며, 새 대상의 과거 `fixed_100` 경고는 더 이상 유효한 제외 사유가 아니다. 기존 스냅샷은 다음 정상 백그라운드 갱신 시 새 정책 버전으로 재계산한다. 재계산 전에도 저장된 유효 중앙값에는 새 임계값을 적용하며, 과거 총수량 경고는 제거한다.

MAIN 기준은 모든 국가·리테일러에 적용한다. 대상일은 중앙값 계산에서 제외하며, 완료된 양수 MAIN 이력을 사용한다. 과거 기본 최소 건수 미달만으로 이력을 제외하지 않는다. 감소율은 반올림 전에 판정하므로 정확히 15% 감소부터 확인 필요이며, 정확히 30% 감소부터 이상이다. 14.95% 감소는 경고하지 않고 29.95% 감소는 확인 필요이다. 통계 표도 MAIN 경고는 MAIN 셀, BSR 경고는 BSR 셀에 표시한다.

## 운영 서버 적용

Ubuntu 서버의 기존 프로젝트 폴더에서 일반 배포 사용자(예: `ubuntu`)로 실행한다. `venv/bin/python`과 기존 `gunicorn` 서비스가 있는 환경을 대상으로 한다. 개발 PC에서 운영 설정을 읽거나 운영 서버 명령을 실행하지 않았다.

배포 스크립트를 처음 받는 이번 한 번은:

```bash
git pull --ff-only
bash scripts/deploy.sh
```

이후 배포는 아래 한 줄이다. 현재 체크아웃된 브랜치를 갱신하며 브랜치를 자동 전환하거나 로컬 변경을 지우지 않는다.

```bash
bash scripts/deploy.sh
```

스크립트가 `git pull --ff-only` → Django 검사 → 통계 테이블 마이그레이션 → 정적 파일 반영 → gunicorn 재시작 → 통계 자동 갱신 등록/시작을 수행한다. 기존 추적 파일에 수정이 있거나 중간 단계가 실패하면 중단한다. 서버 관리에 필요한 `sudo`는 해당 명령에만 사용하며 스크립트 전체를 `sudo`로 실행하지 않는다.

통계는 별도 systemd 작업 `samsung-dsdx-collection-statistics.service`에서 처리하고, 같은 이름의 `.timer`가 15분마다 실행한다. 최초 배포 시에도 즉시 작업을 시작하되 배포 명령은 과거 집계 완료를 기다리지 않는다. 최근 3일을 모든 국가에 먼저 반영하고, 이후 실행마다 국가별 최대 14일의 미집계 이력을 채워 최대 112일을 준비한다. 최초에는 과거 주간 결과가 일부만 보일 수 있으며 차례로 채워진다. 이미 준비된 과거 이력은 반복 조회하지 않고, 오류가 난 이력은 재시도한다. 재부팅 후에도 타이머가 자동 실행된다.

서버에서 자동 갱신 등록 여부를 확인할 때:

```bash
systemctl is-enabled samsung-dsdx-collection-statistics.timer
systemctl list-timers samsung-dsdx-collection-statistics.timer
```

### 필요한 경우에만 수동 집계

자동 배포를 사용하면 아래 명령을 매번 입력할 필요가 없다. 최초 이력을 한 번에 전부 채우거나 특정 과거 날짜를 다시 집계할 때만 사용한다.

```console
python manage.py migrate dx_layer1
python manage.py refresh_collection_statistics --days 112
```

첫 집계는 12주 표시분과 비교 이력을 준비한다. 국가별 실행도 가능하다.

```console
python manage.py refresh_collection_statistics --country SEA --days 112
```

Ubuntu 자동 배포 외의 환경에서는 기존 운영 스케줄러에 다음 명령을 15분 간격으로 등록할 수 있다. 작업 디렉터리는 저장소 루트, 실행 파일은 운영 가상환경의 Python으로 지정한다. 작업이 중첩되면 국가별 DB 잠금으로 같은 국가 집계를 건너뛴다.

```console
python manage.py refresh_collection_statistics --automatic
```

3일보다 오래된 데이터의 재적재/삭제 후에는 해당 **데이터일**을 지정해 다시 집계한다. 이력이 변경되면 이후 28일 비교 결과와 관련 주간 합계도 갱신된다. 같은 명령을 반복해도 수집 건수를 더하지 않고 교체한다.

```console
python manage.py refresh_collection_statistics --country SEA --start 2026-09-15 --end 2026-09-21
```

수동 범위는 최대 120일씩 처리한다. SEA/SEDA는 데이터일에 1일을 더한 검수일을 이용하며 다른 국가는 당일이다. SEA HomeDepot는 2026-09-20부터 대상으로 취급한다. 운영 소스 조회 실패는 0건을 만들지 않으며 기존 건수를 보존하고 갱신 실패로 표시한다. 명령은 실패 건수가 있으면 실패 종료한다.

## 속도 및 갱신 구조

- 원본 테이블 집계는 관리 명령에서만 수행한다. 기존 국가별 Layer1 집계 로직을 재사용하며 개별 SQL에 30초 제한을 둔다.
- Django 기본 DB에 일별 요약, 주별 요약, 집계 잠금 테이블 3개를 추가한다. 기존 원본 테이블은 수정하지 않는다.
- 통계 API는 최대 12개 주간 요약을 한 번 조회한다. Layer1 판정 API는 선택 검수일의 최대 6개 국가 요약을 한 번 조회한다.
- 기존 Layer1 데이터 로딩과 비교 기준 로딩은 독립적이다. 건수는 바로 표시하고 기준을 기다리는 동안 검증 대기로 표시한다. 비교 요청은 8초 제한으로 최대 3회 시도한다. 일시적인 지연/실패가 회복되면 화면을 자동 갱신하며, 날짜를 변경하면 이전 요청과 재시도를 취소한다.
- `unknown`은 관찰 대상임을 의미하지 않는다. 미응답/조회 실패를 모든 리테일러의 ‘관찰 이력 확인 중’ 문구로 표시하지 않는다. 실제 `observing`인 신규 대상에만 상태 칸에 관찰 일수를 한 번 표시하며 BSR 칸에 중복하지 않는다. 반복 실패는 검증 대기 배지의 사유로 구분하고 정상 처리하지 않는다.
- 기준 적용 전에 검수일, 데이터일, 국가, 업체, 제품, 시간대를 대조한다. 배치 ID와 현재 건수는 과거 중앙값의 사용 조건이 아니다. SEA의 별도 건수 API가 더 최신이면 화면에 표시되는 MAIN·BSR로 재판정한다. 저장된 현재일 경고는 재사용하지 않는다.
- 당일 통계가 60분 이상 오래됐거나 갱신 실패라면 검증 대기로 표시한다. 주간 화면에는 마지막 집계 시각을 보여준다.
- 집계 데이터가 없거나 요약 DB 조회가 실패해도 화면 요청에서 원본을 재집계하는 대체 동작은 없다.

## 컬럼 비교와 과거 미해결 이력

컬럼 통계의 날짜 입력은 **검수일**이다. 공통 `resolve_monitoring_date`로 SEA·SEDA는 D-1, 나머지는 D0 데이터일을 구한다. 컬럼 집계와 미수집 조회는 원본 `crawl_datetime` / `crawl_strdatetime` 날짜를 사용하며 SIEL만 기존 업무 시간대 예외를 유지한다. 기존 조회 도구의 날짜 변환은 변경하지 않는다.

전체 미수집은 최신 배치·page_type·redirect 필터를 적용하지 않은 리테일러 원본 행이 0건인 경우다. 기존 수집 완료 기준을 통과한 날짜만 판정하며, 비교 이력 일수와 무관하게 대상·데이터일별 1건으로 표시한다. 같은 날짜의 MAIN·BSR 수집량 이상과 서로 다른 비어 있지 않은 배치 ID 2개 이상도 과거 미해결에 포함한다. 기존 표 아래 NULL 컬럼 판정은 유지한다.

`CollectionIssue`, `CollectionIssueEvent`, `CollectionIssueScan`은 Django 기본 DB에 저장한다. DEBUG 환경의 이력은 운영과 분리한다. **2026-10-01** 또는 등록된 수집 시작일 중 늦은 날짜부터 점검하고, 최초 발견 당시 중앙값·건수·데이터일을 보존한다. 과거 목록은 검수 대상 데이터일보다 엄격히 이전만 표시한다. 검수일이 10/26이면 SEA·SEDA는 10/24까지, 나머지는 10/25까지다. 데일리 대상일은 기존 검증 항목에 남는다.

담당자 확인 기록만으로 해결하지 않으며, 원래 날짜를 재조회해 복구를 검증하거나 사유를 남겨 예외 처리한다. 컬럼 복구는 발견 당시 중앙값의 정상 범위(60% 초과), MAIN·BSR 복구는 발견 당시 기준값과 기존 수집 통계 판정 규칙을 사용한다. 일부 데이터가 들어와 전체 미수집이 해제되어도 수집량 이상이 남아 있으면 계속 표시한다. 조회 실패는 기존 이력과 점검 완료 범위를 보존하고, 화면에서 점검 중·조회 실패를 0건과 구분한다.

MAIN·BSR 정상 확인은 기존 `RetailNormalReview`의 날짜·제품군·리테일러·시간대·배치·건수·판정 근거가 일치할 때만 해당 항목을 목록에서 제외한다. 취소는 다음 목록 조회에 즉시 반영되고, 건수 변경은 다음 원본 재점검에 반영된다. 정상 확인은 복수 배치 문제를 숨기지 않는다. 이력 자체를 삭제하지 않는다.

명시된 시작일이 없는 대상은 10/1과 DB 최초 관측일 중 늦은 날짜부터 점검하며 그 이전은 판정 유보다. 이 기준일을 저장하므로 최초 날짜의 데이터가 나중에 삭제돼도 시작일이 앞으로 이동하지 않는다. 예를 들어 최초 원본 데이터가 10/6이면 10/1~10/5는 미수집으로 만들지 않는다. 9월 데이터는 10월 판정의 이전 28일 기준값 계산에 사용할 수 있다.

기존 15분 자동 작업(`refresh_collection_statistics --automatic`)에서 수집 통계를 갱신한 뒤 미해결을 점검한다. 매 실행 시 과거 대상 최근 3일, 순차 과거 28일, 모든 미해결 날짜를 확인한다. MAIN·BSR은 원래 날짜의 실시간 건수를 기존 통계 규칙으로 평가하며 국가·날짜별 원본 조회를 같은 작업 내에서 공유한다. 최초 전체 점검 완료까지 화면에 점검 범위를 명시한다. 웹에서 직접 조회한 당일 컬럼 비교도 이력에 보존하지만 과거 목록에서는 날짜 경계로 제외한다. 오래된 관측이 더 최신의 복구 검증을 되돌리지 않는다.

배포 시 `0006_recheck_october_collection_issues` 마이그레이션은 점검 완료 위치만 초기화한다. 다음 작업이 10월부터 누락된 MAIN·BSR·배치 문제를 재평가하며 기존 문제와 확인 이력은 보존한다.

`0007_collectionissuescan_policy_version`부터는 점검 정책 버전도 저장한다. 기존 컬럼 검사만 끝낸 기록은 날짜가 최신이어도 새 점검 완료로 인정하지 않는다. 새 기준의 작업이 성공하기 전에는 API가 점검 대기를 반환하고, 작업은 예전 완료 위치와 관계없이 10월부터 재평가한다. 브라우저 새로고침은 저장된 결과 조회이며 서버 점검을 실행하지 않는다. 업데이트 직후 아래 마이그레이션과 재점검이 필요하다. 서버 API가 구버전이면 화면도 완료·0건으로 추정하지 않는다.

별도로 미해결 점검만 실행하려면:

```console
python manage.py migrate dx_layer1 --noinput
python manage.py refresh_collection_issues
python manage.py refresh_collection_issues --country SEA
```

화면의 `새로고침`은 저장된 미해결 조회이고, 상세의 `원래 날짜 복구 재검증`은 해당 데이터일의 원본을 재조회한다. 같은 국가·제품군·리테일러·데이터일은 한 줄로 묶고 문제별 상세 버튼을 제공한다. `조회 SQL`은 전체 건수·원본 행·배치별 건수를 복사하는 기능이며 쿼리를 브라우저에서 실행하지 않는다. 화면의 전체·복구 완료 이력 선택은 제거하고 미해결만 표시한다. 감사 이력과 상세 API는 유지한다.

python tests/test_collection_issues_browser.py
