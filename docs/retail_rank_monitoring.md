# 리테일러 상품 순위 비교

작업 브랜치: `feat/retail-rank-monitoring` (기준: `feat/admin-validation-review`).

Layer 1의 **전체 상품 순위**, **삼성 제품 순위** 메뉴에 각각 SEA, SEDA,
SIEL, SEG, SEM, TSE, SEIB, SEUK 하위 메뉴가 있습니다.

- 전체: `/dx/layer1/rank/all/SEA/`
- 삼성: `/dx/layer1/rank/samsung/SEA/`
- 다른 국가: URL 마지막 국가 코드를 변경하거나 메뉴에서 선택합니다.
- 선택한 국가에 등록된 제품군·리테일러만 조회합니다.
- 첫 화면은 전체 상품, 전일 순위순입니다. 확인 필요 탭은 식별/순위 확인,
  일시 누락 의심, 미발견, 급변 순으로 정렬합니다.
- 상품명, ITEM, SKU를 독립 열로 표시하며 세 항목 모두 검색·CSV 내보내기를 지원합니다.
- 페이지 이동 없이 아래로 스크롤하면 상품이 계속 이어집니다. 화면 아래에 현재
  표시한 상품 수/전체 수를 표시하며, 검색·필터 변경 시 해당 조건의 첫 상품부터
  다시 시작합니다. 추가 조회 실패 시 기존 상품을 유지하고 재시도할 수 있습니다.

## 비교 기준

입력 날짜는 **검수일이 아닌 원본 수집일 D**입니다. D-1, D, D+1을 비교합니다.
기존 검수일 메뉴의 날짜를 순위 메뉴로 자동 전달하지 않습니다.

원본 텍스트 타임스탬프는 `source_date_sql`로 기록된 날짜를 사용합니다.
예: `2026-10-14T21:37:34-04:00` → `2026-10-14`.
기존 SIEL 네이티브 timestamptz의 명시적인 Asia/Seoul 업무일 예외는 유지합니다.
새로운 네이티브 timestamptz 소스는 원본 수집일 근거가 등록되지 않으면 조회를 거부합니다.
Lookup/표시 시각 변환 함수나 원본 수집값은 변경하지 않습니다.

1. 국가·제품군·리테일러별 날짜당 최신 MAIN 배치를 선택합니다. page_type이 없는
   소스 및 Costco, Expert, HomeDepot는 해당 날짜의 최신 배치를 사용합니다.
   기존 정책과 같이 id 역순으로 선택하며 Coppel 건조기는 원본 수집 시각의
   순간값 순서를 먼저 사용합니다. **배치명으로 수집일을 만들지 않습니다.**
2. 같은 배치 안에서 MAIN 순위를 비교합니다. 여러 날짜·배치의 최선 순위를
   섞지 않습니다. 수집 건수 화면의 당일 전체 배치 합산과는 목적이 다릅니다.
3. 상품은 같은 조회 범위 안의 ITEM으로 연결합니다. 같은 SKU라도 ITEM이
   다르면 합치지 않습니다. ITEM 또는 배치 ID가 없으면 확인 대상으로 표시합니다.
4. 동일 ITEM/동일 순위 중복은 한 상품으로 집계하되 원본 행 ID를 보존합니다.
   같은 ITEM에 서로 다른 순위가 있으면 임의 선택하지 않고 복수 순위로 표시합니다.
5. D-1 구간(1–100, 101–200, 201–300)의 상품을 분모로 사용합니다.
   D의 동일 구간 유지, 다른 구간 이동, 300위 내 미발견, 판단 보류를 나눕니다.
   유지율 기준 90/70/50%, 급변 40위는 **검토용 가설**입니다.
6. 상위 100위에서 빠진 상품은 101–300위 이동과 300위 내 미발견으로 분리합니다.
   원본에 301위 이상의 순위가 있으면 그 숫자를 그대로 표시합니다.
   30→350→32는 범위 밖 이동이며 일시 수집 누락으로 분류하지 않습니다.
7. 30→미발견→32는 일시 누락 의심, 80→150→95는 순위 급변입니다.
   D+1에서 사라진 상품도 별도의 확인 대상으로 표시합니다.
8. 하루 전체 데이터가 없거나 유효 순위가 없으면 개별 상품이 전부 사라졌다고
   판정하지 않습니다. 비교/유지율을 보류하고 다음 날 수집 대기를 구분합니다.
9. 전체 상품 목록은 3일 중 한 번이라도 300위 안에 있던 상품과 식별값/순위 확인
   대상을 포함합니다. 따라서 목록 상품 수는 300보다 클 수 있습니다.

원본 조회는 요청한 한 리테일러의 3일만 읽는 read-only 트랜잭션입니다.
연결 제한 3초, SQL 문장별 제한 5초, 최대 15,000행을 적용합니다.
행 한도를 넘기면 부분 결과를 정상 데이터처럼 반환하지 않습니다.
수집 진행 중인 최신 배치의 결과는 잠정값임을 안내합니다.

## 조회 부하와 결과 일관성

- 순위 전용 파일 캐시와 비차단 OS 파일 잠금을 사용합니다. 동일 호스트의
  모든 앱 워커가 같은 경로를 공유하면 동시에 원본을 읽는 순위 작업은 하나입니다.
  요청하지 않은 국가/리테일러를 정기적으로 전수 집계하지 않습니다.
- 새 요청은 완료 결과를 60초간 재사용합니다. 만료 시 백그라운드 스레드가
  갱신하며, 최대 300초 전 결과를 조회 시각 및 갱신 상태와 함께 반환합니다.
  결과가 없으면 HTTP 202 준비 중, 조회 실패 시 HTTP 503을 반환합니다.
  실패를 0건/누락으로 바꾸지 않으며 20초간 자동 재시도를 억제합니다.
- 목록은 20개 상품의 필수 필드만 반환합니다. 요약은 전체 상품 기준으로 한 번
  계산하며 페이지/검색/확인 필요 필터에 따라 유지율 분모가 바뀌지 않습니다.
  상세 근거·URL·서명·확인 이력은 상품 클릭 시 한 건만 조회합니다.
- 화면은 목록 하단에 가까워지면 같은 결과에서 다음 20개를 받아 기존 행 아래에
  추가합니다. 100개 이상도 한 목록에서 연속 확인할 수 있으며, 이미 표시한 행을
  교체하거나 스크롤할 때 원본 DB를 다시 읽지 않습니다. 추가 요청은 하나씩 실행하고
  조건 변경 시 이전 요청을 취소합니다. 최신 브라우저의 자동 감지가 없는 경우에는
  같은 위치에 상품을 추가하는 '상품 더 보기' 버튼을 제공합니다.
- 검색, 페이지 이동, 상세, CSV는 서명된 동일 결과를 사용하며 원본 DB를 다시
  읽지 않습니다. 결과는 생성 후 최대 20분 유효하며 캐시 퇴출/원본 수정 시
  조기 만료될 수 있습니다. 새 수집 확인은 조회 버튼을 누릅니다.
- 확인 기록 저장은 기존 모니터링 캐시를 초기화하지 않습니다. 기존 원본 수정
  경로의 캐시 무효화는 유지하며 순위 결과도 그 세대 변경을 확인합니다.
  외부 수집기의 DB 직접 쓰기는 이 신호가 없으므로 60초 재사용 정책을 따릅니다.
- 기본 경로는 `.cache/rank-monitoring/<환경>`이며 `RANK_CACHE_DIR` 설정으로
  변경할 수 있습니다. 운영 계정이 쓸 수 있는 비공개 로컬 디스크여야 합니다.
  기존 모니터링 캐시/잠금과 분리합니다. 파일 캐시는 호스트 단위이며 여러
  호스트로 확장할 때에는 중앙 작업 큐/캐시로 동시 실행 제한을 공유해야 합니다.
- 워커 재시작 중 갱신은 취소될 수 있으며 다음 조회가 다시 시도합니다.
  첫 조회는 준비 시간이 필요합니다. 요청 작업은 최대 20초 동안 1초 간격으로
  상태를 확인한 뒤 재조회 안내를 표시합니다. 완료 결과를 자동으로 바꿔
  확인 중인 근거를 변경하지 않습니다.

## 삼성 및 SKU

현재 등록된 수집 테이블에는 독립 브랜드 컬럼이 없습니다. 삼성 페이지는
3일 상품명 중 `Samsung`(영문 단어 경계, 대소문자 무관) 또는 `삼성`이 있는
상품을 필터링합니다. 삼성 내부 순위를 새로 매기지 않습니다.
이름에 삼성 호환 등이 포함된 타사 제품은 별도 검토가 필요하며, 정식 브랜드
마스터가 확보되면 이 판별 방식만 교체할 수 있습니다.

SEA TV는 물리적인 sku 컬럼이 없어 기존 `public.tv_item_mst`의 동일
item·리테일러 최신 행에서 가져옵니다. 현재 마스터 값이라는 점을 화면에
표시합니다. 다른 소스는 수집 행의 sku를 사용합니다.

## 확인 기록

상품 확인 창에서 원본 URL을 열고 구매 가능, 품절, 판매 종료, 순위 변동,
수집 오류, 추가 확인 필요 등을 기록합니다. 메모는 필수입니다.

- 원본 DB 상품/순위는 수정하지 않습니다. 자동 점검 신호도 지우지 않습니다.
- Django `default` DB의 `dx_layer1_retailrankreview`에 저장합니다.
- production/test를 분리하고 국가·제품군·리테일러·원본 수집일·상품과
  3일의 배치·순위·원본 ID를 서명된 근거로 묶습니다.
- 전체/삼성 페이지는 동일 상품·동일 비교 근거의 확인 기록을 공유합니다.
- 배치/순위/상품 근거가 바뀌면 기존 확인을 자동 적용하지 않습니다.
  기존 기록과 이력은 DB에 남습니다.
- 수정자, 시각, 메모, 결과를 누적하며 revision으로 동시 수정 충돌을 막습니다.
- 저장 토큰과 원본 비교 결과는 최대 20분 유효합니다. 만료 시 다시 조회합니다.
- 확인 저장소가 없더라도 순위 조회는 가능하며 저장 불가 안내를 표시합니다.

## 서버 적용 명령

**PostgreSQL에 업로드할 SQL은 없습니다.** 원본 수집 테이블·인덱스는 변경하지
않습니다. 코드가 서버에 반영된 후, 프로젝트 루트에서 기존 가상환경으로
Django 기본 DB 마이그레이션을 적용하면 됩니다.

Ubuntu 운영 환경:

```bash
venv/bin/python manage.py migrate dx_layer1 --database default --noinput
venv/bin/python manage.py collectstatic --noinput
sudo systemctl restart gunicorn
```

Windows 로컬 환경:

```powershell
python manage.py migrate dx_layer1 --database default --noinput
```

확인:

```bash
venv/bin/python manage.py showmigrations dx_layer1
venv/bin/python manage.py check
```

`0008_retailrankreview`가 `[X]`이면 확인 기록 저장소가 준비된 것입니다.
마이그레이션을 PostgreSQL의 `dx` alias에 적용하지 않습니다. 기존 배포 스크립트
`scripts/deploy_monitoring.py`도 dx_layer1 마이그레이션 및 collectstatic을 수행합니다.

백엔드 테스트는 메모리 SQLite와 원본 조회 모의 응답을 사용합니다.
브라우저 테스트는 설치된 Edge를 headless로 실행하며 모든 응답을 로컬 fixture로
대체합니다. 실제 원본 DB에 쓰지 않습니다. 테스트 화면 캡처는
`output/diagnostics/rank-monitoring/`에 저장됩니다.

2026-11-09~11의 실제 읽기 전용 확인에서는 등록된 8개 국가, 65개
국가·제품군·리테일러 조합의 조회가 모두 성공했습니다. 이는 실제 사이트의
품절/순위 정당성을 확인한 결과가 아니라 DB 조회 및 비교 경로의 검증입니다.

2026-11-11 로컬 측정(실제 원본 읽기, 네 리테일러 순차 요청):

| 조회 | 이전 응답 크기 | 변경 후 20개 목록 | 변경 후 재조회 처리 시간 |
|---|---:|---:|---:|
| SEA TV Bestbuy | 859,479 B | 12,181 B | 4.8–6.2 ms |
| SEA REF HomeDepot | 925,537 B | 12,644 B | 3.9–4.2 ms |
| SEG TV OTTO | 850,589 B | 11,273 B | 4.4–4.6 ms |
| SEM LDY_DRYER Coppel | 72,703 B | 11,513 B | 1.5–1.7 ms |

위 시간은 Django RequestFactory로 측정한 서버 함수 처리 시간이며 네트워크,
브라우저 렌더링 및 운영 동시 부하를 포함하지 않습니다. 첫 요청은 약 1.5–3 ms에
202 준비 중을 반환했고, 별도 원본 읽기는 약 94–432 ms가 걸렸습니다.
실제 화면의 첫 결과 표시는 1초 상태 확인 간격도 포함합니다.
원본 SQL 실행계획의 전체 스캔 자체를 제거한 변경은 아닙니다. 운영에서 느린
원본 조회가 계속되면 그 리테일러의 실행계획과 수집 쓰기 비용을 확인한 뒤
별도로 인덱스/집계 저장소를 검토합니다. 현재 원본 DB 인덱스 변경은 없습니다.
